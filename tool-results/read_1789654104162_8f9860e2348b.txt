    35→# 1. PRODUCT VISION
    36→
    37→Create a desktop application where the user can type:
    38→
    39→> "Open Chrome, go to my website dashboard, log in, download today's report, rename it with today's date, move it into my Reports folder, and notify me when finished."
    40→
    41→The AI should:
    42→
    43→1. Understand the request.
    44→2. Break it into tasks.
    45→3. Create an execution plan.
    46→4. Ask for confirmation when required.
    47→5. Execute the workflow.
    48→6. Observe the computer when necessary.
    49→7. Recover from common failures.
    50→8. Record every action.
    51→9. Show progress to the user.
    52→10. Provide a final result.
    53→
    54→Another example:
    55→
    56→> "Every Monday at 9 AM, open Excel, process the sales spreadsheet, remove duplicate records, save the cleaned file, and create a summary."
    57→
    58→The system should convert this into a reusable scheduled workflow.
    59→

    62→# 2. CORE DESIGN PRINCIPLE
    63→
    64→Use this architecture:
    65→
    66→**User → AI Planner → Task Graph → Permission Engine → Automation Engine → Computer → Observation → Verification → Result**
    67→
    68→Never allow the AI model to directly execute arbitrary operating-system commands without passing through the application's controlled tool layer.
    69→
    70→The AI should decide:
    71→
    72→**WHAT should happen**
    73→
    74→The automation engine should decide:
    75→
    76→**HOW it can safely happen**
    77→
    78→The security layer should decide:
    79→
    80→**WHETHER it is allowed to happen**
